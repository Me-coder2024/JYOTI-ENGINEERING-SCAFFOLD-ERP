# Rental-only transition

The active workspace is `/rental`; accounts are `/rental/accounting`. Manufacturing pages redirect to rental and manufacturing APIs return 410. Historical manufacturing tables remain intact. Existing manufacturing-only users retain no rental access until an owner changes their role.

Run `npm run db:migrate` before deploying this version. Migration 004 creates rental accounting tables and links every customer to one debtor ledger. It deliberately fails if existing nonblank GSTINs are duplicated. Resolve duplicates with the business owner first; never erase or merge financial history silently. Migration 004 was applied to Supabase after the user confirmed keeping C S CONSTRUCTION GST unchanged and clearing CHOUDHARY CONSTRUCTION GST pending verification. The correction was audited; six customer profiles were linked to six debtor ledgers. Manufacturing accounting contained zero ledgers/vouchers.

Customer creation in Customers automatically creates its accounting ledger in the same database transaction. Editing the customer refreshes ledger details; historical voucher snapshots remain unchanged. Accounts links back to the same customer editor. Other ledgers are created in Accounts. Configure company/opening date before posting.

Material ledger: choose customer, date range and optional item, then Print / PDF or Excel. Outw is dispatch; Inwr is physical return. Pending is opening + issues - receipts, independent of rental locking dates. The layout follows the supplied two-page US Letter reference, with item subtotals and closing totals. Legacy movements without document references show a shortened movement ID. New movements can store a challan/receipt reference. No prices, deposits or payments are included.

Rental invoices retain rental/damage/GST prices. To record payment, create a Receipt voucher, choose the invoice allocation, debit Bank/Cash and credit its automatic customer ledger. The server prevents overpayment and wrong-customer allocations. Invoice details and PDF show current receipts and balance due as of export. Reversal journals remove reversed receipts from the paid total without deleting history. Creating/finalizing an invoice does not automatically post a Sales voucher; link the final invoice in Accounts > Sales to avoid duplicate entry.

GST: normalization, format, state code and check-digit validation are enabled. Blank GST remains allowed for unregistered customers. A nonblank GST must be unique. Live lookup is not connected: set server-only GST_LOOKUP_URL and GST_LOOKUP_KEY after selecting a provider. The adapter contract is HTTPS GET with `gstin` query and Bearer authentication, returning `{name,address,state_code}`. A provider-specific adapter must translate the provider's API to that contract. No provider key is embedded in the browser.

Validation: `TEST_DATABASE_URL` must point at a local database for `node --import tsx tests/rental-shift.integration.ts`. This creates and removes a disposable test database; never point integration tests at Supabase. The earlier rental-isolation baseline is now historical: the user explicitly authorized rental changes in this transition. Do not overwrite it to disguise intentional changes.
